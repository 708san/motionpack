# MotionPack 開発ガバナンス仕様 v1.0

状態: **内部開発方針の初版**（正式公開・ライセンス決定ではない）／作成日: 2026-11-02

## 1. ミッションと適用範囲
MotionPackはゲーム固有のルールを含まない、編集可能なアニメーション画像パッケージ形式とその制作・再生基盤。画像、背景、マスク、骨格、動き、演出、形態差分を分けて管理し、小規模な再生系でオフライン動作できることを目指す。

今回管理するのは **MotionPackを開発するためのAI開発体制**。将来の「画像を制作するためのユーザー向けエージェント」の設計は別プロジェクト・後工程とする。

## 2. 原則
1. 形式・再生系・制作ツール・制作スキルの疎結合。
2. 既存アセット互換性と非破壊編集。破壊的変更は明示的バージョン変更と移行手順が必須。
3. 機能は実測・テスト済みと未実装を分けて表現する。動きの自然さは人間による目視評価も必要。
4. すべての外部アセットは未信頼入力として扱う。
5. 発生する全変更の根拠（Issue/PR、設計判断、テストログ）を残す。
6. 小規模開発の効率を尊重し、11役を常時呼び出さない。委譲はコストと独立性で判断。
7. AI提案とセキュリティ判定は人間の承認の代替ではない。

## 3. 決裁権限
- **人間のメンテナー**: ビジョン／優先順位の重要変更、ライセンス、公開、機密データ・権限変更、破壊的仕様変更の最終承認。
- **Main（統括）**: 通常のIssueの計画・委譲・統合・PR作成。自動テストに失敗した状態を「完成」と報告しない。
- **Planner**: Issue案と優先順位の推奨。最終的なロードマップ変更権は持たない。
- **Architect**: 公開フォーマットの仕様変更評価。コード実装者とは分離してレビュー。
- **Security Auditor / QA / Reviewer**: 検証とリスク評価。自己承認によるマージはしない。
- **GitHub Manager / Release Manager**: 作業準備・チェック・提案を担当。保護設定の緩和や公開は自動実行しない。

## 4. 変更分類と必須レビュー
| 分類 | 例 | 必須確認 |
|---|---|---|
| S（軽微） | typo、内部コメント、小修正 | Main、必要な簡易テスト |
| M（機能） | runtime機能、UI、素材編集処理 | 担当Engineer、Functional QA、Reviewer |
| H（高影響） | 公開フォーマット、パーサ、パッケージ構造、供給網、認証 | Architect、Functional QA、Security、Reviewer、人間の最終判断 |
| V（描画） | 画質、メッシュ、IK、粒子処理 | Motion/Runtime Engineer、Visual QA、Functional QA |
| R（リリース） | 公開配布・タグ・アダプタ公開 | Release Manager、Security、QA、人間の最終承認 |

高影響かつ描画変更など、分類が重複する場合は条件を合算する。テストの省略時は理由と未検証リスクを書く。未通過の必須ゲートを「省略」で置き換えてはいけない。

## 5. 標準フロー
1. Plannerが目的・成功条件・非目標・依存関係と粒度を明記する。
2. Architectが境界・拡張点・互換性を確認（必要な場合）。
3. Mainが関係ファイルを把握し、互いに独立する作業のみサブエージェントに分配。
4. Engineerが実装。実装者は変更理由とテスト結果を残す。
5. Functional QA、Visual QA、Security Auditorが必要な検証を **独立に** 行う。
6. Code Reviewerが仕様、回帰、根拠、複雑化をレビュー。
7. GitHub ManagerがPRのチェック・コメント・Issueリンクを整える。
8. 人間が重要なPR・リリースを承認。通常PRもGitHub上の実際の保護設定に従う。
9. Plannerが残課題と今後の計画を更新。

## 6. 不合格・意見不一致の扱い
- Securityで重大リスク: マージ停止、Issue化して優先修正。
- テストが落ちた: 再現手順とログを保存し、担当実装者へ返す。
- 見た目が不自然: Visual QAが時刻付き画像・動画などの再現条件を提示。
- 意見が割れた: 具体的な検証法を提案し、検証困難ならメンテナーが判断。
- AIが実行できないテスト: 「未実施」と記載し、通過したものと混同しない。

## 7. 対象外（今は設計しない）
- 製品としての画像制作エージェント・各生成モデルの詳細な実装。
- 特定ゲームのコスト・HP・進化ルールなどのゲームデータ。
- 商用化・収益化・正式公開ライセンスの決定。
