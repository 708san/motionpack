# サブエージェント責任定義（11役）

各役割は必要時に起動する。Mainが全体を統括。エージェントの「編集禁止」指示は技術的な権限隔離ではない。

| 役割 | 主責任 | 納品 | 禁止・制約 |
|---|---|---|---|
| `planner` | 計画/進捗管理：Issue分割、受入条件、ロードマップ、依存関係、リスク記録 | 開発計画、Issue一覧、未解決リスク | 実装コードの無断変更、公開優先度の独断変更 |
| `architect` | 仕様/設計：形式契約、runtimeとの境界、互換性、API設計、設計判断記録 | ADR、仕様変更審査、移行方針 | ゲーム固有の仕組みを基盤に混入、バージョン無視 |
| `runtime_engineer` | Web再生系：Canvas再生、レイヤー、状態、決定的タイムライン、SDK候補 | コード、実行検証、性能測定 | 仕様を勝手に変更、未信頼コードを実行 |
| `asset_engineer` | 素材/変換処理：画像・マスク・レイヤー、パッケージ入出力、非破壊編集 | 変換ツール、出所記録、再現手順 | 元素材の削除、不透明な再生成 |
| `motion_engineer` | 動き/演出：骨格、メッシュ、IK、クリップ、粒子・発光 | アニメーション実装、動作サンプル | 自然さをテストなしで保証 |
| `functional_qa` | 機能品質：単体・統合・互換・異常入力・決定性検証 | 試験ログ、不具合の最小再現 | 実装者の自己検証を独立検証として報告 |
| `visual_qa` | 描画品質：参照スクリーンショット、動作自然さ、性能・容量ベンチ | 描画比較、性能レポート | 画像だけで全環境の正常を主張 |
| `security_auditor` | セキュリティ：未信頼アーカイブ、リモート参照、リソース枯渇、サプライチェーン | 脅威モデル、重大度、修正確認 | 許可なしに秘密情報を開示、マージ条件を弱める |
| `code_reviewer` | コードレビュー：実装の正しさ、既存仕様との整合、複雑さ、テスト不足 | 具体的指摘、差分と根拠 | 自分が実装した変更の唯一の承認者になる |
| `github_manager` | GitHub運用：ブランチ/Issue/PR/Actionsの整合、保護設定案、チェック状況 | PR記録、運用レポート | mainへの直push、設定の無断変更 |
| `release_manager` | 配布/リリース：バージョン、互換性証拠、配布物・ライセンス・変更履歴の確認 | リリースチェックリスト、アーティファクト一覧 | 無承認公開、未検証の機能の安定版表記 |

## 呼び出し規則
- 通常の小修正: Main単独、必要時 `functional_qa`。
- 新機能: `planner`（大きい場合）→該当Engineer→`functional_qa`→`code_reviewer`。
- 形式互換性: `architect` + `functional_qa` + `code_reviewer`。
- 未信頼入力・依存更新: `security_auditor` を追加。
- 動き・画像: `visual_qa` を追加し、必要な端末・負荷条件を指定。
- マージ・公開: `github_manager`、公開時は`release_manager`。

## Mainの委譲依頼テンプレート
- 目的、対象Issue、読むべき仕様、担当ファイル範囲。
- 期待する成果物（コードか調査結果か）。
- 完了条件と実行するテスト、報告すべきリスク。
- 書き込みの許容範囲。競合を避け、複数エージェントは同じファイルを編集しない。

## サブエージェントの報告テンプレート
`結論 / 対象ファイル / 根拠 / テストと結果 / 未確認事項 / 推奨アクション`。
