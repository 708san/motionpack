# Validated .motionpack to native Rust pose bridge

**Experimental developer integration.** `tools/native_pose.py` connects the existing process-isolated, bounded package reader to the previously merged native Rust scene API (`mp_scene_sample_v1`). This is the first full-path use of a real `.motionpack` file to calculate a native pose, without a browser or Node.js in the actual sampling path.

## Usage

```sh
cargo build --manifest-path core/Cargo.toml --locked --lib
python3 tools/package.py examples/robot_ik_demo --out dist
python3 -m tools.native_pose dist/robot_ik_demo.motionpack --clip idle --time-ms 600 --out pose.json
python3 -m unittest tests.test_native_archive_pose -v
```

## Supported

- Validates the actual package through the existing isolated archive reader. Neither Python nor Rust executes code embedded in assets.
- Parses the validated manifest into typed Rust C ABI arrays, retaining image asset identifiers and per-variant visual substitutions outside the numerical core.
- Evaluates keyed numeric node properties, loop/nonloop clips, parent transforms, ordered two-bone IK and optional host-provided IK targets.
- Produces the existing `motionpack-pose` version 1 JSON contract, including clip, variant, logical canvas, node local/world transforms, z-order and active declarative effect descriptions.
- `NativePoseSession` validates the package once and retains compiled host-side arrays for repeated `sample` calls; the native library is loaded once. Python/ctypes remains the integration host, not a Unity-ready native package.

## Verification

`tests/test_native_archive_pose.py` compares numeric frames generated by Rust and the canonical JavaScript evaluator for real packaged repository examples across clips, variants, IK overrides and boundary times, on Windows, macOS and Linux. Malformed archives and invalid requests fail with errors. The CLI is smoke tested.

## Remaining work

The bridge does not extract images into Unity, rasterize SVGs, create SpriteRenderers, play animation on Unity's update loop, provide self-contained native apps or claim real-time frame rates. Native/Wasm runtime packaging and Unity Editor tests remain separate milestones. Unity integration must also address authored image asset IDs, per-node layer anchors and effects, lifecycle ownership, and the existing separately supported semantic/autonomy host API.

Raw native pointers are constructed by trusted Python `ctypes` after isolated validation. This is not an OS sandbox for the Rust library; use only trusted code to construct pointer parameters.
