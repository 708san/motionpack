# v1.0 Release Readiness and Announcement Evidence

**Status: not approved for v1.0 release or announcement.** This register maps the governed release gates to evidence and claim limits. It does not change the format contract, select a license, approve residual security risks, or authorize publication.

Audited against GitHub `main` at `1b58828c870e047b3a086889c0b7e3094668d656` on 2026-11-12, after [PR #165](https://github.com/708san/motionpack/pull/165) merged. PRs #155–#165 record and synchronize maintainer-selected v1 planning directions and experimental runtime work; they do not freeze normative behavior. [Issue #120](https://github.com/708san/motionpack/issues/120) defines v1.0 core as a stable format, integrated reader/validator, and loss-aware writer; GUI and AI authoring are outside that core. There is still no normative v1 schema, integrated v1 package reader, or v1 writer. [Issue #120](https://github.com/708san/motionpack/issues/120) records the selected core-shape and SVG-dimension directions. [Issue #154](https://github.com/708san/motionpack/issues/154) records deterministic ZIP/package, asset, numeric, loss-confirmation, and capability directions, including conditional execution-ignore plus opaque preservation for unknown optional capabilities. Exact canonical JSON/numeric behavior, ZIP64 input variants, capability declaration grammar/registry and safe-ignore validation constraints, field ranges/graph limits, asset grammars, public error/report APIs, and other contract details remain open. PR #164 adds only an experimental in-memory PlayerController load/unload lifecycle; it does not load archives. The broad human art/motion review remains incomplete; the approved seal sample is only an additional example. Recheck every status against the release candidate before publication.

## Announcement claim limits

Until the gates above are closed and the maintainer approves release:

- Describe MotionPack as experimental/pre-alpha and the browser player as a reference preview.
- Claims about offline preview, implemented v0.x formats, bounded reader behavior, screenshots, or examples must be scoped to the exact implementation and tests that support them.
- Do not claim v1 compatibility, production-safe handling of arbitrary untrusted packages, a complete sandbox, cross-browser/device parity, a complete artwork-quality review, or AI authoring.
- Public repository visibility does not grant reuse rights. State the selected software license and asset-rights limits only after those decisions and inventories are complete.

## Final release decision

The release manager should attach links to the release-candidate commit, required CI runs, security and visual reviews, compatibility evidence, asset-rights inventory, license decision, checksummed artifacts, and release notes. The maintainer reviews the complete evidence and explicitly approves publication. A green CI run, this register, or a merged PR alone is not release approval.
