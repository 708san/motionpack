# Architecture and distribution

MotionPack consists of independent pieces:
- data format spec and editable source archives
- offline runtime and adapters (currently browser Canvas only)
- command-line authoring, validation and conversion tools
- optional end-user AI authoring skill later
- optional multi-step authoring agents later

The eleven Codex subagents in .codex/agents are **development** roles, not consumer authoring agents.

The editable .motionpack ZIP does not play on its own without a compatible runtime. The generated preview.html is a single self-contained offline browser preview. Its current SVG path loads data-URL assets as browser images and draws them through Canvas 2D; no browser family/version conformance matrix or cross-browser pixel parity is established. This preview path is the only renderer implemented here, not a requirement that all compatible runtimes use the same browser APIs.

The optional `tools/isolated_raster_decoder.py` adapter accepts bounded bytes for explicitly referenced raster assets and returns static RGBA pixel buffers from a separate Pillow process. It is a host-side building block; the offline HTML preview still uses the browser image decoder. Animated WebP and SVG are outside this adapter’s current scope. This API does not change the package manifest or v0.1/v0.2/v0.3 format contract.

## Runtime API direction (experimental)

`runtime/evaluator.js` exports a stateless `MotionPackEvaluator.sample(manifest, options, rig)` function in browser and CommonJS environments. It accepts `clip`, `variant`, a finite nonnegative clip-local `timeMs`, and optional IK target overrides. Missing clip and variant values use manifest defaults. It returns a new node map with variant overrides, sampled tracks and IK applied, plus active effects with elapsed time and progress. It does not read clocks, schedule frames, load images, access the DOM, draw, or mutate the manifest. Looping clips wrap by duration; non-looping clips hold their final sampled pose. Supplying IK targets requires the existing rig implementation. This low-level API assumes the manifest has already passed MotionPack validation; it does not enforce input-size or total-work limits and must not be given raw untrusted package data.

This evaluator is the first separation step, not the final player SDK. The preview remains responsible for animation scheduling and preserves `window.MotionPackPlayer` for existing pages. A later stateful player API must define lifecycle, pause/resume, seek boundaries, events, host clock ownership, multiple instances, rendering adapters and disposal before those behaviors are treated as public contracts. The current generated HTML still uses browser `Image` and Canvas 2D APIs, so the evaluator alone does not establish non-browser playback or secure image decoding.

`runtime/player_controller.js` is an experimental host-driven state controller layered on the evaluator. Create an instance with `MotionPackPlayerController.create({manifest, rig?, clip?, variant?})`; the manifest must already have passed validation, and IK manifests require the existing rig. Instances start `stopped` at time zero. `play(clip?)` selects an optional clip and restarts it from zero; `pause()` and `resume()` transition only from `playing` and `paused`; `stop()` rewinds to zero and enters `stopped`. `advance(deltaMs)` accepts finite nonnegative elapsed milliseconds supplied by the host and returns a fresh sampled pose. Looping clips must use a boolean `loop` value, wrap at duration, and non-looping clips enter `ended` and hold the final pose. `seek(timeMs)` uses clip-local milliseconds, wraps looping clips, clamps non-looping clips, preserves active playback, and puts a stopped or ended controller into `paused` when seeking before the end. `setVariant()` changes the selected variant. `getState()` returns a frozen snapshot; each pose is a fresh evaluator result. `dispose()` is idempotent, drops manifest and rig references, and makes pose/control methods throw while `getState()` reports `disposed`. `setIKTarget(ikId, targetOrNull)` temporarily overrides a known chain's target with a copied finite `[x, y]` pair; `null` removes that override and restores the manifest target plus any clip IK tracks. This controller owns neither a clock nor a renderer, scheduler, DOM node, image, event subscription, or package-loading process. It does not alter v0.1–v0.3 manifests and is not yet a stable public API. The generated preview's frozen `window.MotionPackPlayer` compatibility facade keeps its existing methods and `{clip, variant, pointerIK}` state shape while delegating clip, variant and time state to the controller. The preview catches controller/evaluator failures, displays a generic data error, and stops requesting frames; it does not expose internal exception details.

`runtime/pointer_ik_adapter.js` is an experimental browser-side helper used by the generated preview. When pointer IK is enabled, it maps primary mouse and pen hover plus the primary active touch pointer from the event target's client rectangle to the canvas's logical coordinates and calls the controller's `setIKTarget()`. It clears the temporary target on pointer up, cancel, leave, disable or disposal and removes its listeners on disposal. Browser-native touch gestures remain enabled, so a browser gesture may cancel touch tracking. The helper is not part of the stable runtime API; the frozen preview facade is unchanged. Its rectangle mapping handles scale and translation only, not CSS rotation or skew.

`runtime/hit_test.js` is an experimental, standalone DOM-free query for a sampled pose and a point in logical canvas coordinates. A host explicitly loads the module and calls `MotionPackHitTest.hitTest(pose, [x, y], {assetSizes?, nodeIds?})`; it returns the ID of the topmost matching drawable node, or `null`. It uses transformed rectangular bounds including transparent pixels, excludes nodes with zero opacity, and follows renderer order: lower Z first, with later pose-map entries drawn and selected above earlier entries when Z ties. Nodes with omitted dimensions use host-supplied intrinsic asset sizes keyed by asset ID, matching the renderer's fallback; callers may restrict candidates by node IDs. Candidate filtering is useful for queries but must not omit non-interactive drawables when implementing occlusion.

`runtime/interaction_adapter.js` adds experimental v0.4 preview interactions. Node flags `interaction.hover`, `interaction.tap` and `interaction.click` are opt-in and strictly boolean; all omitted flags are off. The adapter selects the top drawable first and checks that node's flag afterward, so opt-out nodes still occlude. It emits only `{type, nodeId, input}` notifications and never invokes manifest-provided actions. Hover produces enter/leave transitions for mouse and pen; tap requires primary touch down and up on the same top node and is canceled by `pointercancel`; native click accepts mouse/pen only, while accessible host controls can call `MotionPackInteractions.activate(nodeId)` to emit a keyboard click. The generated preview dispatches `motionpack:interaction` events on `window`. Hosts decide whether and how to respond; these events are input notifications, not authorization or proof of trusted user activation. Existing v0.1–v0.3 manifests and the frozen `window.MotionPackPlayer` facade remain unchanged.

No native engine adapters, full-body mesh skinning or reliable automatic image-to-rig conversion are currently available.
