# Public pre-alpha security status

Basic path traversal checks, SVG subset validation, size budgets and negative metadata tests exist. These do not constitute a hardened security audit.

Unresolved (Issue #4):
- The new experimental reader prechecks ZIP entry count and central-directory byte size, then checks paths, file types, duplicate/colliding names, declared sizes and compression ratios. Referenced assets are read with byte limits. The input path is checked for a regular-file target before open and the opened descriptor is checked afterward; `O_NONBLOCK` is used where exposed. `stat` and `open` are not atomic: a concurrently replaced path may still open a special file before descriptor rejection. Python exposes `O_NONBLOCK` on Unix. On platforms without that flag that support blocking special-file types, a replacement after the initial check may block during open. Windows behavior has not been tested; do not treat this as safe handling of attacker-mutable input paths. A small deterministic archive-byte mutation smoke test checks that each input is rejected or returns a dict manifest whose asset IDs match the returned byte-valued assets; at least one mutation must be rejected. Sustained/coverage-guided fuzzing remains unverified. It is not a production-hardened archive boundary; the standard-library ZIP parser is not isolated, and CPU/time defenses remain unverified.
- Complete SVG sanitization for arbitrary renderers, hostile raster media decoding and downstream renderer behavior. `.png`/`.jpg`/`.jpeg`/`.webp` asset paths receive format-specific header dimension checks before decode and share configured dimension/pixel limits. Animated WebP canvas and frame areas are counted, but frame image data is not decoded; JPEG DNL height remains unsupported, content under another extension is classified by that extension, and no decoder is isolated.
- The packager checks raw referenced-asset bytes for a small set of PEM private-key headers and GitHub/OpenAI/AWS credential-like patterns. By default it warns and still packages the bytes; `--fail-on-secret-like` rejects matches before writing outputs. This best-effort scan can miss transformed or pixel-encoded secrets and can produce false positives; it does not certify an asset as safe. Comprehensive secret detection/filtering remains unresolved.
- Sustained fuzzing, dependency review and resource exhaustion defense.

Untrusted packs must not be opened with a production assumption of safety.
