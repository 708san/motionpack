# Public pre-alpha security status

Basic path traversal checks, SVG subset validation, size budgets and negative metadata tests exist. These do not constitute a hardened security audit.

Unresolved (Issue #4):
- The new experimental reader prechecks ZIP entry count and central-directory byte size, then checks paths, file types, duplicate/colliding names, declared sizes and compression ratios. Referenced assets are read with byte limits. The input path is checked for a regular-file target before open and the opened descriptor is checked afterward; `O_NONBLOCK` is used where exposed. `stat` and `open` are not atomic: a concurrently replaced path may still open a special file before descriptor rejection. On platforms without that flag that support blocking special-file types, a replacement after the initial check may block during open. Default `read_package()` still parses in the caller process. The opt-in `read_package_isolated()` snapshots inputs up to 40 MiB, applies a completion deadline and a 40 MiB response cap, kills/reaps its worker, and has a three-OS CI matrix. The deadline cannot interrupt synchronous process creation or OS job setup; that time is deducted once setup returns. Linux applies an address-space ceiling; Windows applies a committed-memory Job Object limit; macOS has no hard whole-process memory limit in this implementation. The wrapper is not a sandbox and does not make attacker-mutable source paths safe. Deterministic negative tests and bounded Atheris targets exercise ZIP reading, SVG validation, and PNG/JPEG/WebP header parsing (15 seconds per target on PRs, 300 seconds per target weekly/manual, 64 KiB maximum input); the raster target does not fuzz image decoders. These finite campaigns do not provide continuous fuzzing. OS-specific containment and resource behavior remain limited by their documented mechanisms.
- The validator now rejects SVG attributes outside the documented per-element allowlists, in addition to its existing static-element and URL checks. Attribute values are not validated against every SVG value grammar. Complete SVG sanitization for arbitrary renderers, hostile raster media decoding and downstream renderer behavior remain unresolved. `.png`/`.jpg`/`.jpeg`/`.webp` asset paths receive format-specific header dimension checks before decode and share configured dimension/pixel limits. Animated WebP canvas and frame areas are counted, but frame image data is not decoded; JPEG DNL height remains unsupported, content under another extension is classified by that extension, and no decoder is isolated.
- The packager checks raw referenced-asset bytes for a small set of PEM private-key headers and GitHub/OpenAI/AWS credential-like patterns. By default it warns and still packages the bytes; `--fail-on-secret-like` rejects matches before writing outputs. This best-effort scan can miss transformed or pixel-encoded secrets and can produce false positives; it does not certify an asset as safe. Comprehensive secret detection/filtering remains unresolved.
- Longer-running fuzzing, ongoing dependency review, stronger macOS memory isolation, complete sandboxing and resource-exhaustion defense beyond the wrapper's stated limits.

Untrusted packs must not be opened with a production assumption of safety.
